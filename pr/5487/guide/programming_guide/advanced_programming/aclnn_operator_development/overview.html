什么是工程化算子开发​

关键术语​

先介绍几个核心概念：

名称含义
自定义算子工程根据算子原型定义编写或者生成的工程骨架，包含原型定义、Tiling实现、核函数（Kernel）实现和CMake编译配置。
算子原型描述算子的输入、输出、属性、数据类型、格式、Shape推导等信息。
Host侧运行在CPU侧的准备逻辑，例如Shape推导、Tiling计算、workspace大小设置。
核函数（Kernel）侧运行在AI Core上的计算逻辑，是算子真正执行计算的部分。
Tiling根据输入Shape、数据类型等信息切分计算任务，并把核函数（Kernel）需要的参数传递到核函数（Kernel）侧。
aclnn单算子API算子工程编译后基于算子原型自动生成的C语言API，应用程序可通过该接口直接调用自定义算子。

工程化开发是什么​

工程化算子开发是指基于自定义算子工程完成算子实现、编译部署和调用验证的开发方式，主要面向CANN相关场景对接：单算子调用场景通过aclnn API完成接入，算子入图场景通过GE图执行链路完成接入。通过工程化开发，算子原型、Host侧Tiling、核函数（Kernel）实现和编译部署配置可以在两类场景中最大化复用同一份交付件。相比手动组织编译流程和分别对接调用链路，工程化开发由msOpGen生成工程骨架，CMake管理编译，编译产物自动包含aclnn API以及入图所需的原型定义等文件，部署时只需安装.run包或者链接静态/动态库。

集成方式​

围绕同一份算子工程，常见集成方式如下：

集成方式说明适用场景
单算子API调用通过生成的aclnn接口直接调用算子，基于C语言API执行算子。算子功能验证、单算子调用。
算子入图补充Shape推导等入图适配代码后，基于GE图执行链路执行自定义算子。图模式、IR构图、多算子组合。
AI框架调用在工程化算子基础上增加框架插件适配后，通过PyTorch/TensorFlow等框架调用自定义算子。融入AI训练或推理流程。

设计与实现​

[基础]（按顺序阅读）：

  • 算子功能设计 — 支持范围、场景划分、核函数（Kernel）组织。
  • 算子原型定义 — 输入输出属性定义、Shape推导。
  • Host侧Tiling实现 — Tiling函数与数据结构、使用约束。
  • 核函数（Kernel）侧算子实现 — 核函数（Kernel）编程与API使用。

[扩展]（遇到具体问题时查阅）：

  • 通过TilingData传递属性信息 — 适用于算子属性需要传递到核函数（Kernel）侧的场景。
  • 多分支策略 — 适用于算子需要按场景拆分核函数（Kernel）入口的场景。
  • GenSimplifiedKey回调实现 — 适用于需要按自定义Key选择预编译binary的场景。
  • 使用高阶API时配套的Tiling实现 — 适用于开发Matmul/Conv等复杂算子的场景。
  • 开启Tiling下沉 — 适用于需要在算子入图场景开启Tiling下沉的场景。

编译与部署​

[基础]：

  • 编译与部署基本流程 — 编译配置、算子包打包与部署。

[扩展]：

  • 多算子包组织 — 多算子包拆分策略。
  • 算子动态库和静态库编译 — 适用于需要以库形式集成到应用的场景。
  • 交叉编译 — 适用于开发环境与运行环境架构不同的场景。
  • 编译过程调试 — 适用于遇到编译问题的场景。
  • 编译加速 — 适用于需要加速构建的场景。
  • simplified key二进制配置JSON — 适用于按自定义Key编译多份binary的场景。
