舍入模式与饱和模式

概述​

Tensor API通过cast接口完成寄存器数据类型转换。对于可能发生精度损失或数值溢出的转换，可以通过编译期cast_options指定舍入模式和饱和模式：

  • 舍入模式：指定精度损失时的舍入方向或规则。
  • 饱和模式：指定转换结果超出目的类型表示范围时的处理方式。

相关接口声明位于tensor_api/experimental/arch/vector/type_conversion.h，相关枚举定义位于tensor_api/experimental/utils/reg_enum.h。

舍入模式​

cast_round_mode用于指定cast的舍入方式。Tensor API使用枚举值配置模式。

枚举值说明示例
rint舍入到最近值；正好位于中间值时舍入到偶数。1.5 → 2，2.5 → 2
round舍入到最近值；正好位于中间值时远离0。1.5 → 2，-1.5 → -2
floor向负无穷方向舍入。1.7 → 1，-1.3 → -2
ceil向正无穷方向舍入。1.3 → 2，-1.7 → -1
trunc向0方向舍入，直接截断小数部分。1.7 → 1，-1.7 → -1
odd最近邻奇数舍入，舍入到最近的奇数。当前仅float → half支持该模式。1.5 → 1
hybrid混合舍入模式，当前用于float或half转换为hifloat8_t。-
unknown未指定舍入方式的预留值。仅在对应类型转换支持该配置时使用。-

配置规则​

  • 表中rint、round、floor、ceil和trunc的示例以浮点转整数为例。浮点转浮点时，舍入目标是目的格式能够表示的数，而不是整数。
  • 舍入模式是cast模板参数opt的一部分，在编译期确定。
  • 不同源类型和目的类型支持的舍入模式不同，必须按照cast的数据类型表配置。
  • 不支持的类型、布局、舍入和饱和配置组合会触发编译期错误。
  • 对不会损失精度的精确扩宽转换，接口可能使用固定的rint配置，但不会额外改变数值。

舍入过程举例​

以下以范围内的float → int16_t转换为例，说明常用舍入模式对正数、负数和中间值的处理：

输入rintroundfloorceiltrunc
1.411121
1.522121
2.523232
-1.4-1-1-2-1-1
-1.5-2-2-2-1-1
-2.5-2-3-3-2-2

其中，rint与round都选择最近值，但中间值的处理不同：2.5在rint模式下得到偶数2，在round模式下得到远离0的3。floor和trunc对负数的处理也不同：-1.4分别得到-2和-1。

odd用于目的浮点格式的奇数舍入，不能套用上述整数取整表。例如，1.5能够由half精确表示，转换为half时不能将其解释为整数1或3。hybrid用于hifloat8_t相关转换的混合舍入，不应按固定的向上、向下或向0取整规则理解。

饱和模式与非饱和模式​

cast_sat_mode用于指定转换结果超出目的类型表示范围时的处理方式。

枚举值说明
not_sat非饱和模式。整数窄化转换超出范围时按目的格式截断；浮点转换保留目的浮点格式支持的特殊值。
sat饱和模式。转换结果超出目的类型范围时钳位到目的类型边界。
unknown不配置饱和模式的预留值，仅用于对应类型转换支持该配置的场景。

配置方法​

开启饱和模式和非饱和模式时，需配置CTRL寄存器。通过asc_get_ctrl接口保存当前值，仅修改所需比特位，并在相关计算结束后恢复原值。

CTRL比特位作用配置值
CTRL[60]选择单指令/API配置或全局饱和配置。0：使用单指令/API配置；1：使用全局配置。
CTRL[59]控制浮点转整数、整数转整数的全局转换饱和模式，仅在CTRL[60] = 1时生效。0：饱和；1：截断。
CTRL[48]控制浮点计算及部分浮点精度转换的全局饱和行为。0：饱和，INF钳位到对应有限边界、NaN转换为0；1：非饱和，保留INF和NaN。
CTRL[50]控制fp8_e8m0_t、fp8_e5m2_t、fp8_e4m3fn_t相关场景的全局饱和模式。0：饱和；1：非饱和。

按cast_options配置​

希望通过cast_options::sat分别选择每条转换的饱和行为时，将CTRL[60]设置为0，再使用cast_sat_mode::sat或cast_sat_mode::not_sat调用cast。CTRL配置在SIMD VF外、执行相关转换之前完成；相关计算结束后恢复：

C++
#include "c_api/spr/spr.h"

const uint64_t saved_ctrl = static_cast<uint64_t>(asc_get_ctrl());
const uint64_t api_ctrl = saved_ctrl & ~(uint64_t{1} << 60);
asc_set_ctrl(api_ctrl);

执行本页配置示例所示的寄存器转换后，在SIMD VF外恢复：

C++
asc_set_ctrl(saved_ctrl);

按全局CTRL配置​

对于浮点转整数或整数转整数，若使用全局模式，将CTRL[60]设置为1，并通过CTRL[59]指定饱和或截断。以下为全局饱和模式的配置片段：

C++
const uint64_t saved_ctrl = static_cast<uint64_t>(asc_get_ctrl());
const uint64_t global_sat_ctrl = (saved_ctrl | (uint64_t{1} << 60)) & ~(uint64_t{1} << 59);
asc_set_ctrl(global_sat_ctrl);

若改为全局截断模式，则使用asc_set_ctrl(global_sat_ctrl | (uint64_t{1} << 59))。全局模式下不能仅根据cast_options::sat判断最终饱和行为，且仍须传入该类型组合支持的cast_options。转换结束后同样使用asc_set_ctrl(saved_ctrl)恢复。

浮点转浮点场景应根据目的类型配置CTRL[48]及适用的CTRL[50]，不能用CTRL[59]代替。FLOAT全局饱和需要先启用全局策略；FLOAT8饱和还需要先启用FLOAT饱和。各模式的适用范围和配置约束请参考asc_set_ctrl和asc_set_saturation_flag。修改CTRL会影响当前核上其他受这些比特位控制的计算，不能直接写入一个固定值而覆盖无关配置。

模式对比​

不同转换场景下的行为如下：

转换场景not_satsat
浮点转整数超出范围时按目的格式截断；正负无穷返回目的类型对应边界值；NaN返回0。超出范围时返回目的类型边界值；正负无穷分别钳位到对应边界；NaN返回0。
浮点转浮点目的类型支持时保留NaN和正负无穷；有限值超出范围时按目的浮点格式转换。超出范围时钳位到目的浮点类型边界；NaN转换为0。
整数转浮点该场景不提供饱和模式，使用舍入模式控制可能的精度损失。不支持。
整数转整数窄化转换超出范围时截断为目的格式的数据宽度；扩宽转换通常保持数值。超出范围时钳位到目的类型边界。

例如，int32_t转换为uint8_t时，输入256在not_sat模式下结果为0，在sat模式下结果为255；输入-1在sat模式下结果为0。

整数转整数示例​

以int32_t → uint8_t为例，非饱和模式保留低8 bit，而不是将数值钳位到范围内：

输入非饱和结果饱和结果
100100100
256（0x00000100）0（0x00）255
511（0x000001FF）255（0xFF）255
-1（0xFFFFFFFF）255（0xFF）0

扩宽转换通常保持数值，但不能据此推断任意有符号到无符号转换。例如，int16_t → uint32_t要求opt.sat为not_sat，底层转换仍采用饱和语义，负数转换为0。请以cast的数据类型说明和对应转换约束为准。

以float → half为例，目的类型最大有限正数为65504.0。下表使用rint，并假设CTRL已按对应模式配置：

上述结果不能推广到所有低精度浮点格式或所有舍入模式。其他目的格式对NaN、无穷和有限溢出值的处理，以对应类型转换的约束为准。

配置示例​

以下片段在SIMD VF或SIMD被调函数内将float转换为half，使用向最近偶数舍入和饱和模式。src为已完成数据和mask初始化的reg_tensor<float>，调用前须按配置方法设置CTRL饱和策略：

C++
static constexpr asc::te::experimental::cast_options options = {
    asc::te::experimental::cast_layout::zero,
    asc::te::experimental::cast_round_mode::rint,
    asc::te::experimental::cast_sat_mode::sat,
};

auto dst = asc::te::experimental::cast<half, options>(src);

cast_layout用于描述源、目的类型位宽不同时较小元素在寄存器中的位置，不属于舍入或饱和模式。具体布局要求请参考cast_layout。
