应用场景​

FP8/FP4主要与量化/反量化（Quantize/AntiQuantize）类接口配合使用：支持从half、bfloat16_t、float类型量化到fp8_e5m2_t、fp8_e4m3fn_t、hifloat8_t、int8_t等类型，以及相应的反量化。FP8与FP4还可作为MX格式的私有元素，与fp8_e8m0_t共享缩放因子组合使用，参见本节"MX缩放计算"部分。矩阵计算（Mmad）同样支持fp4x2_e2m1_t、fp4x2_e1m2_t、fp8_e4m3fn_t、fp8_e5m2_t作为输入。具体接口请参见数据类型转换与量化API。

MX缩放计算（Microscaling Matmul）​

MX数据格式（Microscaling）​

现有浮点数格式或数值范围不足，或精度不高；若同时满足数值范围和精度的要求，则内存占用过大，数据存储与传输成本高。为此，业内提出了微缩放（Microscaling，MX）格式：以块为单位编码数据，在保持低位宽的同时通过共享缩放因子灵活表示不同范围的数据，使8位及以下位宽的数据也能支撑稳健的AI训练和推理精度。

MX的核心思想：

  • 张量切分固定大小Block（块），每块共用一个独立缩放因子；
  • 块内元素用极低比特浮点（4bit/8bit）存储；
  • 缩放因子用E8M0（纯指数8bit，仅代表2的幂次），硬件乘算极快。

MX格式的数据由三部分构成：

  • 共享缩放因子X，位宽为w bits：块级缩放比例因子，决定数据块中所有元素的动态范围；
  • 私有元素Pi，位宽为d bits：数据块中的每个低位宽数据元素，所有k个元素Pi有相同的位宽和数据类型，并且共享一个缩放因子X，经X调整后共同表示高精度的浮点数或整数；
  • 块大小k：组成一个数据块的低比特数据的数量。

每个包含k个元素的块使用（w + k*d）位编码，元素的数据类型和缩放因子可以独立选择。

MX缩放计算（MxMatmul）​

MxMatmul（全称Microscaling Matmul）为带有量化系数的矩阵乘法：左矩阵和右矩阵均有对应的量化系数矩阵，计算公式为：

C = (scaleA ⊗ A) * (scaleB ⊗ B) + Bias

其中"⊗"表示广播乘法，左/右矩阵与左/右量化系数矩阵做逐元素乘积时，K方向上每32个元素共享一个量化因子。各操作数的形状为：

  • A为左矩阵，形状为[M, K]；scaleA为左量化系数矩阵，形状为[M, K/32]；
  • B为右矩阵，形状为[K, N]；scaleB为右量化系数矩阵，形状为[K/32, N]；
  • C为目的操作数，形状为[M, N]；
  • Bias为矩阵乘偏置，形状为[1, N]，对结果矩阵的每一行进行偏置。

MX配置方式​

MX缩放计算的接口分为三类：

  • 基础API：MmadMx执行MX矩阵乘加计算；数据搬运使用LoadData（2D MX搬运），左右矩阵以512字节分形为单位搬入L0A/L0B Buffer，量化系数矩阵以32字节分形为单位搬入专用的L0A_MX/L0B_MX Buffer（各4KB）。
  • C API：asc_mmad_mx执行MX矩阵乘加，asc_copy_l12l0a_mx、asc_copy_l12l0b_mx完成数据搬运。
  • Matmul高阶API：Host侧Tiling通过SetMadType配置MatrixMadType::MXMODE开启MxMatmul场景，通过SetScaleAType、SetScaleBType设置量化系数矩阵的类型信息；Kernel侧通过MatmulTypeWithScale定义A、scaleA、B、scaleB的类型，并以MatmulWithScalePolicy策略创建Matmul对象，通过SetTensorScaleA、SetTensorScaleB设置量化系数矩阵。

矩阵计算前，需通过量化接口将half、bfloat16_t、float等类型量化为MX格式的私有元素；计算完成后，可通过反量化接口还原。Quantize与AntiQuantize支持这些类型与fp8_e5m2_t、fp8_e4m3fn_t、fp4x2_e2m1_t、fp4x2_e1m2_t、hifloat8_t、int8_t等低位宽类型的互转。

MX矩阵搬运与计算为Ascend 950PR&950DT系列产品新增能力。完整的使用流程与代码示例请参见MxMatmul场景与mmad_mx样例。

MX缩放计算仅适用于SIMD编程范式：MxMatmul为矩阵计算特性，相关接口均为SIMD API；SIMT编程范式不提供矩阵计算能力。SIMD与SIMT混合编程场景下，需在SIMD侧完成MX的配置与计算。

HF32​

HF32（half-fp32）是面向Cube（矩阵计算）的高性能float32数据格式，在fp32的32bit位宽内以更短的尾数换取更高的矩阵计算性能。它不是独立的用户数据类型：没有对应的C++类型名，fp32数据在参与矩阵计算前被舍入为HF32格式，中间计算使用HF32，最终运算结果仍以fp32格式输出，以保证后续处理的兼容性。

HF32与float32的差异仅在尾数位宽度：Atlas A3系列与Atlas A2系列产品的HF32格式见下图；Ascend 950PR&950DT系列产品的HF32格式尾数位为10位。

HF计算模式​

HF计算模式是面向Cube（矩阵计算）的高性能float32计算模式，其作用对象是fp32矩阵乘：在输入矩阵A、B均为fp32数据类型的场景下，开启HF计算模式后，fp32数据在执行矩阵乘法运算之前会被转换并舍入为HF32格式参与计算。矩阵乘单元因此可用接近half的吞吐处理fp32输入，可显著提升计算性能，代价是输入端的一次舍入带来的精度损失。中间计算与累加仍在HF32/更宽的内部精度上进行，最终运算结果仍以fp32格式输出，对使用者透明。

fp32转HF32的舍入模式与HF计算模式的开关通过以下接口配置，各接口的产品支持情况请参见对应接口文档：

  • 基础API：SetHF32Mode开启或关闭HF32模式，开启后L0A Buffer/L0B Buffer中的fp32数据将在参与Mmad计算之前被舍入为HF32；
  • C API：asc_enable_hf32开启、asc_disable_hf32关闭、asc_set_hf32_round_mode设置舍入模式。
  • Matmul高阶API：Kernel侧通过SetHF32设置；Tiling侧的SetMadType对应MatrixMadType::HF32，当前版本暂不支持HF32模式设置，仅可用于开启MxMatmul场景。

HF32的完整特性说明请参见HF32关键特性。
