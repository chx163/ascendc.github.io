通过类型对齐提升搬运效率

【优先级】中

【描述】SIMT编程模式下，结构体类型对齐会影响Global Memory的访存效率。Ascend 950PR/Ascend 950DT支持1B、2B、4B、8B、16B五种位宽的访存指令。在数据总量不变时，可通过类型对齐到更大的位宽，提升数据搬运效率。

【样例介绍】设置总搬运量MEM_BYTES为512MiB，构造多组不同大小、不同对齐方式的结构体TData，依次将长度为num_elements的输入数组d_idata整体复制到输出数组d_odata进行测试，对比非对齐与使用alignas类型对齐后的耗时差异。具体代码可参考类型对齐优化搬运效率最佳实践样例，其中核函数（Kernel）实现如下：

C++
constexpr uint32_t THREAD_COUNT = 2048;                  // threads per block
constexpr size_t MEM_BYTES = 512ULL * 1024ULL * 1024ULL; // 总数据量512 MiB
uint32_t num_elements = static_cast<uint32_t>(MEM_BYTES / sizeof(TData));

template <class TData>
__global__ __launch_bounds__(THREAD_COUNT) void aligned_type_kernel(
    TData* d_odata, TData* d_idata, uint32_t num_elements)
{
    const uint32_t tid = blockIdx.x * blockDim.x + threadIdx.x;
    const uint32_t num_threads = blockDim.x * gridDim.x;
    for (uint32_t pos = tid; pos < num_elements; pos += num_threads) {
        d_odata[pos] = d_idata[pos];
    }
}

下面以Align4、Misalign4这两个结构体作为典型代表展示对照场景。

【反例】Misalign4未设置显式对齐，默认alignof受字段类型限制，编译器只能选用窄位宽的访存指令。

C++
struct Misalign4 {
    unsigned char r, g, b, a;
}; // sizeof=4, alignof=1

性能数据如下：

Task Duration(us)aiv_total_cycles
81223.02134028903.60

上述结构体由字段类型决定alignof=1，编译器只能用8-bit档位搬运每个元素，aiv_total_cycles和Task Duration都较高。

【正例】使用alignas提升对齐属性，编译器可以选用更宽位宽的访存指令。

C++
struct alignas(4) Align4 {
    unsigned char r, g, b, a;
}; // sizeof=4, alignof=4

性能数据如下：

Task Duration(us)aiv_total_cycles
27889.3346005213.32

Align4将alignof从1B提升到4B，编译器可以选用32-bit档位完成单元素搬运，aiv_total_cycles和Task Duration都显著减小。

对比多组结构体大小不同的样例，在类型对齐前后耗时差异如下：

结构体大小对齐Task Duration(us)非对齐Task Duration(us)非对齐Task Duration/对齐Task Duration

4B (2×u8 + u16)27854.56 (alignof=4)46666.11 (alignof=2)1.68x

测试结果表明：在数据总量不变的时候，相同大小的结构体，类型对齐可以提升搬运效率。以4B结构体为例，随着结构体类型对齐位宽从1B对齐提升至4B，非对齐Task Duration/对齐Task Duration逐步下降，说明非对齐与对齐的耗时差距逐步缩小。此外，同大小的4B结构体，字段组合形式、有无填充位，都不会对搬运效率产生影响。

【总结】SIMT算子使用结构体搬运数据时，结构体类型对齐能让访存指令以更大位宽合并完成搬运，降低搬运耗时。Ascend 950PR/Ascend 950DT支持1B、2B、4B、8B、16B位宽的访存指令，因此建议使用时在不超过结构体大小的情况下，尽量选择更高的位宽。
