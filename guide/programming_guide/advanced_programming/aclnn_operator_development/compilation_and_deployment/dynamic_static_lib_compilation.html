算子动态库和静态库编译

本文是扩展内容，介绍如何将自定义算子工程编译为动态库或静态库，并在应用程序或图模式场景中使用这些库。常规部署场景优先参考编译与部署基本流程生成custom_opp_*.run算子包；只有当应用需要直接链接算子库，或希望把算子库集成到其他工程中时，再考虑使用动态库或静态库编译。与.run算子包预先安装到OPP目录不同，动态库或静态库方式在进程拉起后会由运行时创建临时目录，将算子包结构恢复到临时目录中并从该目录加载算子相关文件，进程退出前再删除该临时目录。

算子动态库和静态库​

算子动态库和静态库编译，是将算子核函数（Kernel）实现、Host侧Tiling实现、入图适配文件，以及自动生成的单算子调用代码编译链接成库文件的过程。编译后会同时生成单算子调用aclnn头文件和算子原型定义头文件，分别用于单算子调用和算子入图场景。

和.run算子包相比，动态库或静态库更适合被应用工程直接链接；.run算子包更适合安装到OPP的vendors/<vendor_name>路径后供运行环境使用。不同产物形态的典型使用方式如下。

产物形态CMake配置主要产物典型使用方式
算子包TYPE RUNcustom_opp_*.run安装到OPP的vendors/<vendor_name>路径，供运行环境使用。
动态库TYPE SHAREDlibcust_opapi.so应用或图模式流程动态链接。
静态库TYPE STATIClib${vendor_name}.a应用工程静态链接，通过aclnn方式执行算子。

算子动态库和静态库编译支持以下产品范围：

  • Ascend 950PR/Ascend 950DT
  • Atlas A3训练系列产品 / Atlas A3推理系列产品
  • Atlas A2训练系列产品 / Atlas A2推理系列产品

开始前需完成以下准备：

  • 已完成算子原型定义、Host侧Tiling实现和核函数（Kernel）侧实现；
  • 工程使用find_package(ASC)和npu_op_package组织编译；
  • 已配置CANN环境变量，例如执行source ${install_path}/cann/set_env.sh；
  • 已在CMakePresets.json或CMake命令中配置vendor_name、ASCEND_COMPUTE_UNIT、CMAKE_INSTALL_PREFIX等参数。

编译动态库​

动态库编译时，将npu_op_package的TYPE设置为SHARED。以快速入门里的AddCustom为例，将顶层CMakeLists.txt里的npu_op_package配置修改如下：

CMake
set(package_name ${vendor_name})
npu_op_package(${package_name}
    TYPE SHARED
    CONFIG
        INSTALL_PATH ${CMAKE_INSTALL_PREFIX}
)

执行编译和安装：

Bash
cmake -S . -B build_out --preset=default
cmake --build build_out --target binary install -j$(nproc)

说明

TYPE RUN场景通常执行package目标，生成custom_opp_*.run，后续再运行该.run包安装到目标OPP路径。TYPE SHARED和TYPE STATIC场景通常执行install目标，直接将头文件、库文件和CMake package配置安装到${CMAKE_INSTALL_PREFIX}，供应用工程通过find_package或直接链接方式集成。

编译成功后，主要产物位于${CMAKE_INSTALL_PREFIX}：

Text
├── include
│   ├── aclnn_*.h       // 单算子调用aclnn头文件
│   └── op_proto.h      // 算子原型定义头文件
└── lib
    ├── cmake
    │   └── ${vendor_name}
    │       ├── ${vendor_name}-config.cmake  // 安装文件，定义了项目中的配置选项和变量
    │       └── ${vendor_name}-targets.cmake // 安装文件，定义动态库的构建目标${vendor_name}::${vendor_name}，便于开发者使用动态库，自动处理库的依赖关系
    └── libcust_opapi.so    // 动态库libcust_opapi.so，用于动态链接

编译静态库​

静态库编译时，将npu_op_package的TYPE设置为STATIC。

CMake
set(package_name ${vendor_name})
npu_op_package(${package_name}
    TYPE STATIC
    CONFIG
        INSTALL_PATH ${CMAKE_INSTALL_PREFIX}
)

执行编译和安装：

Bash
cmake -S . -B build_out --preset=default
cmake --build build_out --target binary install -j$(nproc)

编译成功后，主要产物位于${CMAKE_INSTALL_PREFIX}：

Text
├── include
│   ├── aclnn_*.h   // 单算子调用aclnn头文件
│   └── op_proto.h  // 算子原型定义头文件
└── lib
    ├── cmake
    │   └── ${vendor_name}
    │       ├── ${vendor_name}-config.cmake  // 安装文件，定义了项目中的配置选项和变量
    │       └── ${vendor_name}-targets.cmake // 安装文件，定义静态库的构建目标${vendor_name}::${vendor_name}，便于开发者使用静态库，自动处理库的依赖关系
    └── lib${vendor_name}.a // 算子静态库

说明

TYPE SHARED和TYPE STATIC是两种产物形态。实际生成哪些库，以本次npu_op_package的TYPE配置和安装目录中的产物为准。

单算子调用场景集成​

动态库静态库调用之前，需要把自定义算子包路径添加到LD_LIBRARY_PATH环境变量的首部，供系统动态链接器查找算子动态库，执行以下命令：

Bash
# ${CMAKE_INSTALL_PREFIX}需要换成自定义算子包路径的绝对路径
export LD_LIBRARY_PATH=${CMAKE_INSTALL_PREFIX}/lib/:${LD_LIBRARY_PATH}

之后调用方的应用工程可以通过find_package导入算子库，然后链接到自己的可执行文件或业务库中。以快速入门里的AddCustom调用为例，向CMakeLists.txt里添加${vendor_name}库搜索，并链接，示例如下：

动态库集成​

CMake
find_package(${vendor_name} REQUIRED    # ${vendor_name}为编译生成的算子package名称，需要用户替换为实际的算子package名称
    PATHS ${CUST_PKG_PATH}  # ${CUST_PKG_PATH}需要用户替换为编译生成的算子package的存放路径，
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE # op_runner需要替换成调用方的目标名
    nnopbase
    acl_rt
    ${vendor_name}::${vendor_name}  # 已自动包含相关的target依赖，需要把${vendor_name}替换为实际的算子package名称
)

其中${CUST_PKG_PATH}是${CMAKE_INSTALL_PREFIX}/lib/cmake/${vendor_name}。find_package(${vendor_name} ...)导入的目标名为${vendor_name}::${vendor_name}，该目标在TYPE SHARED模式下指向libcust_opapi.so。

静态库集成​

CMake
find_package(${vendor_name} REQUIRED    # ${vendor_name}为编译生成的算子package名称，需要用户替换为实际的算子package名称
    PATHS ${CUST_PKG_PATH}  # ${CUST_PKG_PATH}需要用户替换为编译生成的算子package的存放路径，
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE # op_runner需要替换成调用方的目标名
    nnopbase
    rt2_registry
    acl_rt
    ${vendor_name}::${vendor_name}  # 已自动包含相关的target依赖，需要把${vendor_name}替换为实际的算子package名称
)

${vendor_name}::${vendor_name}在TYPE STATIC模式下指向lib${vendor_name}.a。 静态库集成的完整样例可参考custom_op_static_lib。

静态库和动态库混合使用​

如果一个应用同时集成多个算子库，可分别指定各自的package查找路径：

CMake
find_package(${vendor_name1} REQUIRED     # ${vendor_name1}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH_1}              # ${CUST_PKG_PATH_1}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)
find_package(${vendor_name2} REQUIRED     # ${vendor_name2}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH_2}              # ${CUST_PKG_PATH_2}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE
    ${vendor_name1}::${vendor_name1}    # 已自动包含相关的静态库target依赖
    ${vendor_name2}::${vendor_name2}    # 已自动包含相关的静态库target依赖
)

算子入图场景配置​

算子入图场景下，需要配置ASCEND_CUSTOM_OPP_PATH环境变量，将动态库libcust_opapi.so所在目录添加到该环境变量首部。由GE框架在图编译和执行时根据该环境变量搜索算子动态库并使用。环境变量位置越靠前，算子的优先级越高。

Bash
export ASCEND_CUSTOM_OPP_PATH=${CMAKE_INSTALL_PREFIX}/lib/:${ASCEND_CUSTOM_OPP_PATH}

动态库编译和算子包编译功能同时使用时，前者生成的动态库优先级更高。 如下示例中，path1和path3是算子包的指定安装目录，path2和path4是动态库编译时的CMAKE_INSTALL_PREFIX，则编译产物的优先级为2>4>1>3。

Bash
ASCEND_CUSTOM_OPP_PATH=<path1>/vendors/vendor_name1:<path2>/lib/:<path3>/vendors/vendor_name3:<path4>/lib/

如果开发者通过Ascend Graph进行图开发，除了配置环境变量的方式，也可以采用直接在应用程序的编译文件中链接动态库libcust_opapi.so的方式。Ascend Graph图开发的相关信息请参考《图引擎开发指南》。动态库链接方式的so加载优先级高于环境变量配置方式。

多厂商和同名动态库处理​

多个算子工程生成的动态库默认都叫libcust_opapi.so。多个厂商的算子库集成到一个项目时，如果只是通过不同安装路径分别查找和链接，可以用不同的CUST_PKG_PATH区分。

CMake
# 分别指定不同厂商的算子库路径
find_package(${vendor_name1} REQUIRED
    PATHS ${CUST_PKG_PATH_1}              #指向厂商1的算子库安装路径
    NO_DEFAULT_PATH
)
find_package(${vendor_name2} REQUIRED
    PATHS ${CUST_PKG_PATH_2}              #指向厂商2的算子库安装路径
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE
    ...
    ${vendor_name1}::${vendor_name1}
    ${vendor_name2}::${vendor_name2}
    ...
)

如果需要将多个动态库集成到同一个公共动态库，或在同一应用中避免文件名冲突，可在编译前顶层的CMakeLists.txt里为动态库设置不同输出名，之后再编译安装动态库，在npu_op_package之后添加set_target_properties修改：

CMake
npu_op_package(${package_name}
    TYPE SHARED
    CONFIG
        INSTALL_PATH ${CMAKE_BINARY_DIR}/
)

set_target_properties(${package_name} PROPERTIES
    OUTPUT_NAME xxxxxxx
)

旧版工程模板说明​

部分旧版工程模板通过ASCEND_PACK_SHARED_LIBRARY=True控制动态库和静态库编译：

JSON
"ASCEND_PACK_SHARED_LIBRARY": {
    "type": "BOOL",
    "value": "True"
}

如果工程已经使用npu_op_package(... TYPE RUN/SHARED/STATIC ...)，则产物形态由TYPE参数决定，不再通过ASCEND_PACK_SHARED_LIBRARY控制。
