CMake函数参考

本文是参考内容，整理算子工程编译过程涉及的CMake函数接口，供需要深入了解编译机制的高级开发者查阅。

概述​

自定义算子工程的CMakeLists.txt由开发者直接编写。为便于开发者组织编译脚本，CANN软件包中将算子工程编译所需的CMake脚本打包为CMake modules，开发者可通过find_package(ASC REQUIRED)查找并使用这些函数。

本文说明算子工程编译过程中使用的8个CMake函数，按用途分为Package类、Library类、其他三类。

函数一览​

分类函数功能
Packagenpu_op_package创建一个package。
Packagenpu_op_package_add将目标或文件添加到package中。
Librarynpu_op_library创建Host侧库。
Librarynpu_op_kernel_library创建核函数（Kernel）侧库。
Librarynpu_op_kernel_options添加核函数（Kernel）目标编译选项。
Librarynpu_op_kernel_sources描述核函数（Kernel）目标的源码信息。
Librarynpu_op_device_tiling_library创建Device侧Tiling库。
其他npu_op_code_gen执行代码生成过程，生成aclnn单算子调用代码和入图所需的原型定义代码。

Package类函数​

npu_op_package​

创建一个package。

CMake
npu_op_package(<package_name>
    TYPE <RUN|SHARED|STATIC>
    [CONFIG <key> <value> ...]
)

参数说明：

  • <package_name>（必选）：package的名称。
  • TYPE <type>（必选）：package的类型，取值为RUN、SHARED、STATIC。分别对应算子run包形式、算子动态库形式与算子静态库形式。
  • CONFIG <key> <value> ...（可选）：用于配置package的内容和输出位置。各配置项以“参数名 参数值”的形式写在CONFIG之后，支持以下选项：
    • ENABLE_SOURCE_PACKAGE <value>：是否将源码打包到package中，默认使用工程中ENABLE_SOURCE_PACKAGE的值（未设置时为True）。
    • ENABLE_BINARY_PACKAGE <value>：是否将二进制文件打包到package中，默认使用工程中ENABLE_BINARY_PACKAGE的值（未设置时为True）。SHARED和STATIC模式下，必须开启此选项。
    • INSTALL_PATH <path>：指定构建产物的输出路径，例如生成的run包存放位置。默认使用ASCENDC_INSTALL_PREFIX：通常为构建目录；设置了CMAKE_INSTALL_PREFIX时，则使用该路径。
    • ENABLE_CPACK <value>：是否生成run包，仅用于RUN模式，默认为True。设置为False后，执行install目标会将目录和文件安装到INSTALL_PATH下，不再生成run包。
    • ENABLE_DEFAULT_PACKAGE_NAME_RULE <value>：默认为True，RUN模式下安装包默认命名为custom_opp_<os>_<arch>.run；设置为False时命名为<package_name>.run。
    • VENDOR_NAME <name>：算子包的厂商名称，默认为<package_name>，用于确定包内的vendors/<name>目录名。

示例：

CMake
set(package_name ${vendor_name})
npu_op_package(${package_name}                     # package name
    TYPE RUN                                       #指定编译产物形态，[RUN|STATIC|SHARED]
    CONFIG
        ENABLE_SOURCE_PACKAGE True                 #是否将源码打包到package中
        ENABLE_BINARY_PACKAGE True                 #是否编译核函数（Kernel）二进制
        INSTALL_PATH ${CMAKE_BINARY_DIR}/          # package的安装位置
)

npu_op_package_add​

将目标或文件添加到package中。

CMake
# 添加目标
npu_op_package_add(<package_name> LIBRARY <target_name1> [<target_name2>...]
    [PACKAGE_PATH <pkg_path>])
# 添加文件，仅给run包模式使用
npu_op_package_add(<package_name> FILES <file_name1> [<file_name2>...] TYPE <ACLNN|GRAPH>)
npu_op_package_add(<package_name> FILES <file_name1> [<file_name2>...] PACKAGE_PATH <pkg_path>)

参数说明：

  • <package_name>（必选）：package的名称。

LIBRARY和FILES必须选择一个，不能同时使用。

  • LIBRARY <target_name1> [<target_name2>...]：指定需要添加到package中的库目标。添加前，需先通过对应的npu_op_*_library函数定义该目标。
  • FILES <file_name1> [<file_name2>...]：指定需要添加到package中的文件，仅支持RUN模式。添加文件时，还需通过TYPE或PACKAGE_PATH指定包内位置，否则文件不会被安装。
  • [TYPE <target_type>]（可选）：指定文件类型，将文件安装到对应的目录中，取值为ACLNN、GRAPH。配置为ACLNN，会将文件打包至run包目录下aclnn单算子调用头文件所在目录；配置为GRAPH，会将文件打包至run包目录下入图原型定义头文件目录下。
  • [PACKAGE_PATH <pkg_path>]（可选）：指定文件或Host侧库在run包中的存放位置。与npu_op_package的INSTALL_PATH不同，此参数设置的是包内目录。
    • 添加文件（FILES）时：填写相对于packages/vendors/<vendor_name>/的路径，例如include。PACKAGE_PATH与TYPE只能选择一个。
    • 添加Host侧库（LIBRARY）时：填写相对于包根目录的路径，例如packages/vendors/customize/op_api，用于替换该类库的默认目录。

同一次调用中，每种库类型只处理最后一个目标。例如，同时传入两个TILING目标时，只处理后一个。因此，多个同类库应分次添加；同时传入多个核函数库还会产生警告。

示例：

CMake
# 添加Host侧相关library
npu_op_package_add(${package_name}
    LIBRARY
        cust_optiling
        cust_opapi
        cust_op_proto
)

# 添加核函数（Kernel）侧相关library
npu_op_package_add(${package_name}
    LIBRARY ascendc_kernels
)

Library类函数​

说明

本节npu_op_kernel_options/npu_op_kernel_sources的SOC_SERIES/COMPUTE_UNIT参数，与编译配置中工程级的ASCEND_SOC_SERIES/ASCEND_COMPUTE_UNIT变量是两个不同层次的概念，参数名相同但含义不同，容易混淆：

层次配置项作用
全局ASCEND_SOC_SERIES（或ASCEND_COMPUTE_UNIT），工程级CMake变量决定整个工程为哪些AI处理器系列构建产物
细粒度本节函数的SOC_SERIES/COMPUTE_UNIT参数在全局已配置的范围内，这一条编译选项或核函数（Kernel）源码具体用在哪些型号上

npu_op_library​

创建Host侧库。

CMake
npu_op_library(<library_name> <library_type> <files>...
    [CONFIG <key> <value> ...])

参数说明：

  • <library_name>（必选）：Host侧库的名称。
  • <library_type>（必选）：Host库的类型，可选值为TILING、ACLNN、GRAPH、TF_PLUGIN、ONNX_PLUGIN。
    • TILING：Tiling相关库。
    • ACLNN：aclnn单算子调用库。
    • GRAPH：算子入图所需的算子原型库。
    • TF_PLUGIN：TensorFlow框架适配相关库。
    • ONNX_PLUGIN：ONNX框架适配相关库。
  • <files>...（必选）：设置参与编译的源文件，相对路径以当前源码目录为基准。
  • CONFIG <key> <value> ...（可选）：用于配置run包中Host侧动态库的名称，支持以下开关，参数值可填写True或False。开启后，动态库使用<library_name>作为库名。
    • SET_OPAPI_NAME：用于ACLNN库，默认库名为cust_opapi。
    • SET_TILING_NAME：用于TILING库，默认库名为cust_opmaster_rt2.0。
    • SET_OP_PROTO_NAME：用于GRAPH库，默认库名为cust_opsproto_rt2.0。

修改Tiling库或原型库的名称时，CMake会提示兼容性警告。通常保留默认名称即可。

<library_type>需使用上述大写形式。ACLNN、TILING和GRAPH先配置目标文件的编译，再由npu_op_package_add配置最终库的链接；TF_PLUGIN和ONNX_PLUGIN直接配置动态库的编译和链接，默认库名分别为cust_tf_parsers和cust_onnx_parsers。上述函数只配置构建任务，实际编译和链接在执行构建命令时完成。

示例：

下面的代码放在Host侧CMakeLists.txt中。调用前，需已通过npu_op_package创建${package_name}算子包（TYPE RUN），并通过npu_op_code_gen在${ASCEND_AUTOGEN_PATH}中生成代码；${ops_srcs}为参与代码生成的Host侧源码列表。

CMake
# 配置aclnn单算子调用库，使用默认库名cust_opapi
file(GLOB autogen_aclnn_src ${ASCEND_AUTOGEN_PATH}/aclnn_*.cpp)
set_source_files_properties(${autogen_aclnn_src} PROPERTIES GENERATED TRUE)
npu_op_library(cust_opapi ACLNN
    ${autogen_aclnn_src}
)

# 配置算子原型库，入图场景需要，使用默认库名cust_opsproto_rt2.0
file(GLOB proto_src ${ASCEND_AUTOGEN_PATH}/op_proto.cc)
set_source_files_properties(${proto_src} PROPERTIES GENERATED TRUE)
npu_op_library(cust_op_proto GRAPH
    ${ops_srcs}
    ${proto_src}
)

# 配置Tiling库，使用默认库名cust_opmaster_rt2.0
file(GLOB fallback_src ${ASCEND_AUTOGEN_PATH}/fallback_*.cpp)
set_source_files_properties(${fallback_src} PROPERTIES GENERATED TRUE)
npu_op_library(cust_optiling TILING
    ${ops_srcs}
    ${fallback_src}
)

# 将上述目标加入算子包，并配置最终动态库的链接和安装
npu_op_package_add(${package_name}
    LIBRARY cust_opapi cust_op_proto cust_optiling
)

如需将aclnn动态库命名为libmy_opapi.so，可将上例中的npu_op_library(cust_opapi ACLNN ...)替换为：

CMake
npu_op_library(my_opapi ACLNN
    ${autogen_aclnn_src}
    CONFIG SET_OPAPI_NAME True
)

同时，将npu_op_package_add中的cust_opapi改为my_opapi。CONFIG中的值是是否启用自定义库名的开关，实际库名由第一个参数my_opapi决定。

npu_op_kernel_library​

配置核函数（Kernel）侧库，指定源码目录和依赖的Tiling库。调用后，还需通过npu_op_package_add将其加入package，才能生成相应的编译和打包任务。

CMake
npu_op_kernel_library(<target_name> SRC_BASE <path> TILING_LIBRARY <tiling_target>)

参数说明：

  • <target_name>（必选）：目标的名称。
  • SRC_BASE <path>（必选）：指定核函数（Kernel）源码的base目录，要求配置绝对路径。例如示例中的op_kernel目录的绝对路径。
  • TILING_LIBRARY <tiling_target>（必选）：指定通过npu_op_library(... TILING ...)声明的Tiling目标。

示例：

CMake
npu_op_kernel_library(ascendc_kernels
    SRC_BASE ${CMAKE_SOURCE_DIR}/op_kernel/
    TILING_LIBRARY cust_optiling
)

npu_op_kernel_options​

添加核函数（Kernel）目标编译选项。

CMake
npu_op_kernel_options(<target_name> <op_type> [COMPUTE_UNIT <soc_version>... | SOC_SERIES <series>...] OPTIONS …)

参数说明：

  • <target_name>（必选）：目标的名称。
  • <op_type>（必选）：指定编译选项的生效范围。填写ALL表示对所有算子生效；填写具体的算子类型（如AddCustom）表示仅对该算子生效。
  • [COMPUTE_UNIT <soc_version>...]（可选）：用于设置算子在具体AI处理器型号上的编译选项，不填写该选项时默认对所有型号生效。与SOC_SERIES不能同时使用。
  • [SOC_SERIES <series>...]（可选）：用于按AI处理器系列设置编译选项。输入不区分大小写；与COMPUTE_UNIT不能同时使用。SOC_SERIES关键字后必须提供至少一个值；同一次调用同时提供SOC_SERIES和COMPUTE_UNIT，或只提供SOC_SERIES关键字不提供值，CMake配置阶段会报错。

说明 其中，AI处理器型号soc_version请通过以下方式获取：

  • 针对如下产品：在安装AI处理器的服务器执行npu-smi info命令进行查询，获取Name信息。实际配置值为AscendName，例如Name取值为xxxyy，实际配置值为Ascendxxxyy。

    Atlas A2系列产品

    Atlas 200I/500 A2推理产品

    Atlas推理系列产品

    Atlas训练系列产品

  • 针对Atlas A3系列产品，在安装AI处理器的服务器执行npu-smi info -t board -i <id> -c <chip_id>命令进行查询，获取Chip Name和NPU Name信息，实际配置值为Chip Name_NPU Name。例如Chip Name取值为Ascendxxx，NPU Name取值为1234，实际配置值为Ascendxxx_1234。其中：
    id：设备id，通过npu-smi info -l命令查出的NPU ID即为设备id，命令中表示为<id>。
    chip_id：芯片id，通过npu-smi info -m命令查出的Chip ID即为芯片id，命令中表示为<chip_id>。

  • 针对Ascend 950PR&950DT系列产品，在安装AI处理器的服务器执行npu-smi info -t board -i <id>命令进行查询，获取Chip Name和NPU Name信息，实际配置值为Chip Name_NPU Name。例如Chip Name取值为Ascendxxx，NPU Name取值为1234，实际配置值为Ascendxxx_1234。
    其中：id为设备id，通过npu-smi info -l命令查出的NPU ID即为设备id，命令中表示为<id>。
  • OPTIONS …（必选）：核函数编译选项，至少提供一个值。普通选项传给编译器；--save-temp-files、--tiling_key、--kernel-template-input等选项由构建脚本转换为对应的编译配置。
    • --cce-auto-sync：开启毕昇编译器自动同步，由编译器自动插入部分同步指令。自定义算子开发工程默认开启auto-sync（--cce-auto-sync=on），无需重复设置；可通过--cce-auto-sync=off关闭。
    • --cce-auto-sync-log=<file>：将编译器自动插入同步指令的信息输出到指定文件。需同时设置-g，以获取对应的源码行号。

示例：

CMake
npu_op_kernel_options(ascendc_kernels ALL OPTIONS --save-temp-files -g)   #为算子添加编译选项

npu_op_kernel_options(ascendc_kernels AddCustom SOC_SERIES Ascendxxx Ascendyyy OPTIONS -DASCENDC_DEBUG)

下面以AddCustom为例，将自动同步日志输出到构建目录下的add_custom_auto_sync.log。工程默认已开启auto-sync，因此只需添加日志选项和-g：

CMake
npu_op_kernel_options(ascendc_kernels AddCustom
    OPTIONS -g "--cce-auto-sync-log=${CMAKE_CURRENT_BINARY_DIR}/add_custom_auto_sync.log"
)

npu_op_kernel_sources​

描述核函数（Kernel）目标的源码信息，包括设置算子的核函数（Kernel）实现文件和源码路径等。

CMake
npu_op_kernel_sources(<target_name> [OP_TYPE <op_type>] [KERNEL_DIR <path>] [COMPUTE_UNIT <soc_version>... | SOC_SERIES <series>...] [KERNEL_FILE <file>])

参数说明：

  • <target_name>（必选）：目标的名称。
  • [OP_TYPE <op_type>]（可选）：算子类型，必须与KERNEL_FILE同时存在。不指定时，配置对所有算子生效。
  • [KERNEL_DIR <path>]（可选）：指定核函数（Kernel）源码相对于SRC_BASE的相对路径。若算子的源码文件没有平铺在SRC_BASE目录（通过npu_op_kernel_library设置）下，可以通过KERNEL_DIR指定特定目录。
  • [COMPUTE_UNIT <soc_version>...]（可选）：设置KERNEL_FILE在指定型号生效。默认KERNEL_FILE对所有型号生效。与SOC_SERIES不能同时使用。
  • [SOC_SERIES <series>...]（可选）：设置KERNEL_FILE在指定系列生效。输入不区分大小写；与COMPUTE_UNIT不能同时使用，SOC_SERIES关键字后必须提供至少一个值；同一次调用同时提供SOC_SERIES和COMPUTE_UNIT，或只提供SOC_SERIES关键字不提供值，CMake配置阶段会报错。
  • [KERNEL_FILE <file>]（可选）：指定算子入口的核函数（Kernel）实现文件名。若算子的核函数（Kernel）实现cpp文件需要自定义命名，需同时指定OP_TYPE（算子类型）和KERNEL_FILE（核函数（Kernel）实现cpp文件名），以配置两者之间的对应关系。不配置时，核函数（Kernel）实现cpp文件名和OpType之间需满足转换规则，参考命名转换规则对照表。

示例：

CMake
npu_op_kernel_sources(ascendc_kernels
    OP_TYPE AddCustom
    KERNEL_DIR ./Add
    COMPUTE_UNIT Ascendxxxyy
    KERNEL_FILE add_custom.cpp
)

也可以使用SOC_SERIES按系列指定：

CMake
npu_op_kernel_sources(ascendc_kernels
    OP_TYPE AddCustom
    KERNEL_DIR ./Add
    SOC_SERIES Ascendxxx
    KERNEL_FILE add_custom.cpp
)

如果同一算子在不同AI处理器系列上需要不同的核函数（Kernel）实现，可多次调用npu_op_kernel_sources，分别用SOC_SERIES指定各自生效的范围：

以下ascendxxx1、ascendxxx2和ascendxxx3为不同AI处理器系列的构建目标占位符，请替换为实际取值。

CMake
npu_op_kernel_sources(ascendc_kernels
    OP_TYPE AddCustom
    SOC_SERIES ascendxxx1 ascendxxx2
    KERNEL_FILE add_custom_v220.cpp
)
npu_op_kernel_sources(ascendc_kernels
    OP_TYPE AddCustom
    SOC_SERIES ascendxxx3
    KERNEL_FILE add_custom_v310.cpp
)

npu_op_device_tiling_library​

创建用于Tiling下沉的Device侧Tiling库。创建后，需通过npu_op_package_add将其加入package，package的类型仅支持RUN（run包模式）。

CMake
npu_op_device_tiling_library(<target_name> <type> <files>)

参数说明：

  • <target_name>（必选）：目标的名称。
  • <type>（必选）：指定Tiling产物的类型。支持取值为SHARED、STATIC。
  • <files>（必选）：指定Tiling源码文件。

示例：

CMake
npu_op_device_tiling_library(device_tiling SHARED
    device_tiling_impl.cpp
)
npu_op_package_add(${package_name} LIBRARY device_tiling)

其他​

npu_op_code_gen​

执行代码生成过程，生成aclnn单算子调用代码和入图所需的原型定义代码。

CMake
npu_op_code_gen(SRC <src_files>...
    OUT_DIR <output_dir>
    PACKAGE <pkg_name>
    [COMPILE_OPTIONS <options>...]
    [LINK_OPTIONS <options>...]
    [JOBS <count>]
    [JOIN_OP_DEF <True|False>]
    [OPTIONS <key> <value> ...]
)

参数说明：

  • SRC <src_files>（必选）：参与代码生成的源文件范围。

  • OUT_DIR <output_dir>（必选）：生成代码的输出路径。

  • PACKAGE <pkg_name>（必选）：指定生成代码的package名称。

  • COMPILE_OPTIONS <options>...（可选）：设置Host侧原型代码的编译选项，用于生成libascend_all_ops.so。核函数编译选项请通过npu_op_kernel_options设置。

  • LINK_OPTIONS <options>...（可选）：设置生成libascend_all_ops.so时的链接选项。

  • JOBS <count>（可选）：设置Host侧原型代码的编译并行数，必须为正整数。

  • JOIN_OP_DEF <True|False>（可选）：设置生成型号配置的方式，默认为False。参数值区分大小写，仅支持True和False；其他值会产生警告，并按False处理。

    • False：根据工程中ASCEND_SOC_SERIES或ASCEND_COMPUTE_UNIT指定的构建目标生成型号配置。
    • True：根据算子原型中AddConfig注册的型号生成配置。后续仍按工程指定的目标编译核函数，因此AddConfig需覆盖这些目标。

    该参数与是否使用CMakePresets.json无关，也不会改变工程的构建目标。

  • OPTIONS <key> <value> ...（可选）：设置opbuild的代码生成选项，各选项以“参数名 参数值”的形式提供：

    • OPS_PROJECT_NAME：设置生成代码的项目名称。
    • OPS_DIRECT_ACCESS_PREFIX：设置直接调用接口的名称前缀。
    • OPS_ACLNN_GEN：控制是否生成aclnn代码。
    • OPS_ENABLE_SOURCE_PACKAGE：设置源码发布配置。
    • OPS_VENDOR_NAME：设置代码生成使用的厂商名称。
    • OPS_PROTO_SEPARATE：控制是否按算子分别生成原型文件。

该函数在执行cmake配置工程时生成代码，包括aclnn调用代码、原型定义、Tiling辅助代码和型号配置等。请先创建package，再调用本函数；代码生成完成后，才能使用生成的文件，以及npu_op_kernel_options、npu_op_kernel_sources和npu_op_kernel_library。

示例：

CMake
aux_source_directory(${CMAKE_CURRENT_SOURCE_DIR} ops_srcs)
npu_op_code_gen(
    SRC ${ops_srcs}
    PACKAGE ${package_name}
    COMPILE_OPTIONS -g
    OUT_DIR ${ASCEND_AUTOGEN_PATH}
    JOIN_OP_DEF False
)
